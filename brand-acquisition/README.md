# brand-acquisition — поиск и привлечение белорусских брендов на ichiba.by

Отдельная от кода маркетплейса папка: база брендов, скрипт проверки и оценки, шаблоны сообщений, процесс и CRM.
Код маркетплейса не трогается.

**Репозиторий публичный**, поэтому в git только скрипт и документация. База, CRM, выгрузки и `REPORT.md`
(в нём контакты и пометки о рисках брендов) — только локально, см. `.gitignore`. Делайте их резервную копию
отдельно, например в личном облаке.

| Файл | Что внутри |
|---|---|
| `REPORT.md` | Итог исследования: сколько найдено и проверено, топ-20 с объяснением, план на первые 10 брендов, пробелы |
| `output/ichiba_brands.xlsx` | Рабочая таблица: Топ-20, База (свой продукт), На доп. проверку, Исключены, CRM, Критерии оценки |
| `output/*.csv` | То же в CSV (UTF-8 с BOM — открывается в Excel) |
| `data/brands.json` | Мастер-база: все поля, источники, результаты проверки, разбивка баллов |
| `data/crm.csv` | CRM — ведётся руками, скрипт только добавляет новые бренды |
| `data/overrides.json` | Ручные правки поверх данных (ключ — ID бренда, поля — названия колонок таблицы) |
| `data/seeds/*.json` | Найденные бренды по направлениям поиска (формат — `data/seeds/SCHEMA.md`) |
| `data/seeds/source_pages.txt` | Страницы-подборки для `discover` |
| `scripts/pipeline.py` | Сбор → проверка → оценка → экспорт |
| `SCORING.md` | Система оценки 0–100 и группы A/B/C |
| `ICHIBA_FACTS.md` | Что площадка реально даёт брендам сейчас, а чего нет — опора для писем |
| `outreach/messages.md` | Письмо, Instagram, Telegram, шаблон, повторные касания, варианты по типам брендов, возражения |
| `PROCESS.md` | Воронка, что автоматизировано, CRM, KPI |
| `EXPANDING.md` | Как расширять базу дальше |

## Установка

Нужен Python 3.10+.

```bash
pip install -r brand-acquisition/requirements.txt
```

## Запуск

```bash
python brand-acquisition/scripts/pipeline.py all
```

`all` = `ingest` → `verify` → `score` → `export`. Шаги можно запускать по отдельности:

```bash
python brand-acquisition/scripts/pipeline.py ingest      # свести seeds/*.json в data/brands.json без дублей
python brand-acquisition/scripts/pipeline.py discover    # новые кандидаты со страниц-подборок → data/leads_discovered.csv
python brand-acquisition/scripts/pipeline.py verify      # проверка сайтов и Telegram (повторно за день не проверяет; --force)
python brand-acquisition/scripts/pipeline.py score       # баллы и группы
python brand-acquisition/scripts/pipeline.py export      # CSV + XLSX в output/
```

Повторный запуск безопасен: бренды склеиваются по домену сайта, нику Instagram/Telegram/TikTok и названию,
дата обнаружения (`first_seen`) сохраняется, заполненные поля не перетираются (расхождения пишутся в `conflicts`),
CRM не перезаписывается, ответы сайтов кешируются на 7 дней в `data/cache/`.

## Что проверяется автоматически, а что нет

| Источник | Как | Ограничения |
|---|---|---|
| Сайт бренда | Главная + до 4 страниц «Контакты/О нас/Сотрудничество/Опт»: код ответа, email (в т.ч. защищённые Cloudflare), телефоны +375, ссылки на соцсети | Учитывает robots.txt, пауза 1,5 с на хост, свой User-Agent. Сайты на JS без серверного HTML могут не отдать контакты |
| Telegram | Публичная страница `t.me/s/<канал>`: название, подписчики, дата последнего поста | Только публичные каналы; личные аккаунты — без данных |
| Instagram, TikTok, VK, Facebook | **Не открываются** | Правила площадок запрещают автоматический сбор. Ссылка считается подтверждённой, если она стоит на официальном сайте бренда; остальное — ручная проверка (открыть профиль, посмотреть последний пост) |
| Email | «Проверен», если найден на официальном сайте | Доставляемость (SMTP-проверка) не делается — это было бы похоже на спам-разведку |

Статус контактов в таблице: «проверен на официальном сайте» → «соцсеть подтверждена» → «из стороннего источника —
проверить вручную» → «контакт не найден».

## Ручные правки

`data/overrides.json`:

```json
{
  "brandname-1a2b3c": {
    "Аргумент для первого сообщения": "Зацепил дроп ...",
    "Заметки": "Ответили в Telegram, просят созвон"
  }
}
```

Правки применяются при экспорте и не теряются при повторных запусках. Чтобы исправить сам факт (например, бренд
оказался реселлером) — поправьте запись в `data/brands.json` (`own_product_status`) и запустите `score` и `export`.
