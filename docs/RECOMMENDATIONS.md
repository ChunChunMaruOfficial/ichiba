# Рекомендации «Для вас» — ichiba

> Как устроены рекомендации у больших площадок, что из этого подходит нам и что сделано. Код: `server/src/recommendations/`
> (модель — `taste.ts`, сбор сигналов — `recommendations.service.ts`), замеры — `server/scripts/recs-eval.ts`.

## 1. Как это делают большие

| Кто | Что делают | Что берём |
|---|---|---|
| **Pinterest — PinnerSage** (KDD 2020) | У человека не один вектор вкуса, а несколько: действия кластеризуются (Ward), каждый кластер — отдельный «интерес». Средний вектор «гранж + офис» попадает в серую середину, которая не нравится никому | Идею нескольких вкусов. Сами кластеры на наших объёмах проиграли «ближайшим понравившимся» — см. замеры |
| **Pinterest — Pixie** (WWW 2018) | Случайные блуждания по графу «пины ↔ доски»: «кто сохранил это, сохранил и то». Даёт >80% вовлечённости Pinterest | Пока нет: у нас мало людей и каждая вещь уникальна (одна штука). Включать, когда будут тысячи активных покупателей |
| **Pinterest — TransAct** (KDD 2023) | Последние действия в реальном времени важнее давних: короткий интерес сессии поверх долгого профиля. +11% сохранений, −10% скрытий | Действия последних 30 минут весят ×2 |
| **Pinterest — Homefeed** | Кандидаты из разных источников, отдельные модели, смешивание с квотами, разнообразие (round robin, DPP) | Слоты «разведки» и мягкое разнообразие |
| **Etsy** (Code as Craft, arXiv 1812.04407) | Отбор кандидатов → ранжирование. Разные действия — разный умысел: «смотрел» и «положил в корзину» — разные сигналы | Веса сигналов по силе намерения |
| **Stitch Fix — Latent Style / Style Shuffle** | Общее пространство «клиенты + вещи»; быстрые «нравится / нет» по карточкам дают профиль с первого дня | У нас уже есть свайп-онбординг на 20 карточек — то же самое |
| **Zalando — Fashion DNA** | Векторы вещей по фото и атрибутам, вкус клиента — точка в том же пространстве; помогает на холодном старте | Векторы фото (Marqo-FashionSigLIP, уже считаются для поиска по фото) |
| **Vinted** (вакансии команды Recommender Relevance) | Сотни миллионов уникальных вещей «в одном экземпляре» → нельзя опираться на историю самой вещи, только на её содержание; реальное время, разнообразие интересов | Ставка на содержание вещи (фото + признаки), а не на историю её покупок |
| **YouTube / Kuaishou / новостные ленты** (arXiv 2308.13249, 2101.04328, 2006.04153) | Негативные сигналы: «не интересно», короткий просмотр (клик-ошибка), показ без клика — слабый минус; учёт позиции | Быстрый уход со страницы, «не моё», «не интересно» и «усталость от показов» |

## 2. Наша технология

**Сигналы** (что делает человек → вес; веса затухают вдвое за 14 дней, последние 30 минут ×2):

| Действие | Вес | Где пишется |
|---|---|---|
| Открыл вещь | +1 | `listings.service.ts` |
| Долго смотрел (20+ с или 3+ фото) | +2 | `POST /listings/:id/engagement` при уходе со страницы |
| Ушёл за 4 с, не листая фото | −1 (гасит просмотр) | то же |
| Приблизил фото двумя пальцами (лента или страница вещи) | +2 (раз в 30 мин на вещь) | `POST /listings/:id/zoom` |
| Фильтр / текстовый поиск | +2 / +3 к признакам | поиск |
| Поиск по фото | +3 к лучшему совпадению | `photo-search.ts` |
| ♡ / свайп вправо | +5 | избранное, свайп |
| Корзина / предложение цены | +6 | корзина, `offers.ts` |
| Написал продавцу о вещи | +7 (раз в месяц на вещь) | `chat.ts` |
| Запрос на покупку | +8 | `requests.service.ts` |
| Купил (сделка завершена) | +4 сверху | `requests.service.ts` |
| Подписался на продавца | +10 | подписки |
| Свайп влево «не моё» | −3, вещь скрыта на неделю | свайп |
| «Не интересно» | −6, вещь скрыта навсегда | страница вещи |
| Лента показала, но не открыл | штраф растёт с числом показов за 14 дней | `POST /feed/impressions`, таблица `FeedImpression` |

**Профиль** (`buildProfile`): из сигналов — веса признаков (стиль, категория, подкатегория, бренд, размер, цвет, пол,
продавец, ценовой коридор 20–80 перцентиль) и списки понравившихся / отвергнутых вещей с векторами фото.

**Оценка вещи** (`score`), всё в одной шкале (z-оценка по кандидатам):
1. **Признаки** — прежние правила.
2. **Вид** — средняя близость к ближайшим понравившимся вещам (треть истории, 1…5 штук). Ближайшие, а не среднее:
   каждый вкус человека ищется отдельно (идея PinnerSage), но без кластеризации.
3. **Минус «похоже на отвергнутое»** — вещь ближе 0.9 по фото к тому, что человек отверг.
4. Популярность, свежесть (72 ч), **минус «усталость»**: первый показ бесплатный, каждый следующий без клика — штраф.

**Сборка ленты** (`feedOrder`): подходящие профилю — сначала; каждый 8-й слот — из популярного остального (разведка,
чтобы вкус мог расшириться); мягкое разнообразие — следующая вещь — лучшая из 8 ближайших со штрафом за повтор вида
вещи; не больше 3 подряд от одного продавца. Порядок держится 30 минут, пока человек листает; первая страница
пересчитывается не чаще раза в минуту.

**«Похожие» на странице вещи** — к прежним правилам добавлена близость фото (z-оценка, вес 2); хеш картинки — только
если у вещи ещё нет вектора.

Векторы — модель, которая индексирует все фото бесплатно (локальная Marqo-FashionSigLIP); Gemini — только если локальная
выключена. Вид вещи = среднее векторов её фото (без фото дефектов).

## 3. Замеры

Реальных историй пока мало (локально 4 человека), поэтому мерили на «покупателях-симуляциях», у каждого вкус задан
**пятью разными способами**, чтобы ни один метод не выигрывал «на своём поле»: один стиль; один продавец; вид по фото;
категория в одной ценовой трети; 2–3 вкуса сразу; длинная история. Покупатель совершил несколько действий, плюс 3
случайных клика; остальной его вкус спрятан. Метрика — сколько спрятанного попало на первую страницу (24 вещи).

Локальная база, 364 вещи в продаже, 815 покупателей (`npx tsx scripts/recs-eval.ts --personas 120`):

| | Один стиль | Продавец | Вид | Категория+цена | 2 вкуса | 3 вкуса | Длинная история | **Всего** | Видов вещей на 1-й странице |
|---|---|---|---|---|---|---|---|---|---|
| Было (правила) | 61% | 26% | 31% | 52% | 33% | 34% | 37% | **39%** | 7.9 |
| **Стало** | 62% | 28% | 49% | 70% | 38% | 42% | 47% | **48%** | 7.0 |
| Стало, без фото | 63% | 31% | 37% | 68% | 38% | 40% | 41% | 45% | 7.0 |
| Только оценка, без правил ленты | 65% | 31% | 56% | 79% | 42% | 47% | 56% | 53% | 4.0 |

«Похожие»: доля первых 8 из того же вкуса — **30% → 36%** (растёт и «стиль», и «категория+цена», не только «вид»).

**Проверено и отвергнуто** (не возвращать без нового замера):
- Кластеры вкусов (Ward, PinnerSage) и медоиды — не лучше «ближайших понравившихся» при наших историях, сложнее.
- Средний вектор профиля — чуть хуже на 2–3 вкусах и длинных историях.
- Жёсткое «не два одного вида подряд» и разведка каждым 5-м слотом — −5…−8 п. к попаданию; заменено мягким.
- Штраф за похожесть фото соседних карточек — без эффекта, убран.
- Хеш картинки рядом с вектором в «Похожих» — без эффекта.

Разница «без правил ленты» (53%) и «стало» (48%) — сознательная цена разнообразия и разведки: офлайн её пользу не
измерить, только A/B на живых людях.

## 4. Что дальше (после возвращения Railway)

1. Задеплоить миграцию `20261109090000_feed_impressions` и код; через 2–3 недели прогнать `recs-eval.ts` на прод-базе —
   там появятся реальные истории (блок `real` в отчёте).
2. A/B: половина пользователей на старом ранжировании — сравнить ♡, корзины, запросы с «Для вас».
3. Рекомендации гостям: история просмотров в браузере → «Для вас» без входа (большая часть посетителей — гости).
4. Когда станет много покупателей — «кто смотрел это, смотрел и…» (Pixie-подобные блуждания) как третий источник.
5. Объединить векторы Gemini и локальной модели (как в поиске по фото), если на проде у Gemini покрыты все фото.
6. «Собери образ»: дополняющие вещи (низ к верху) по образам `Look`, а не только похожие.
