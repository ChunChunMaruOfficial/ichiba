# Как опубликовать статью в журнале и чек-лист приёмки

## Как опубликовать

1. Возьмите бриф из `docs/journal/briefs/<slug>.md`. Slug статьи = slug брифа (для серий — slug части, предложенный
   в брифе). Имя файла и есть адрес: `/journal/<slug>`.
2. Создайте `client/content/journal/<slug>.mdx`. Пока статья не готова — `draft: true`: черновик виден только в
   режиме разработки, в прод не попадает.
3. Заполните frontmatter. Контракт полей — `client/src/lib/journal.ts`; обязательные: `title`, `description`,
   `rubric`, `publishedAt`. Остальные — по чек-листу ниже они тоже нужны.

   ```yaml
   ---
   title: "Где продать одежду в Беларуси в 2026"        # ≤ 56 символов: это <title> и H1
   description: "Куфар, комиссионки, ресейл-платформы и ichiba: комиссии, сроки, выплаты в одной таблице."  # ≤ 158
   rubric: sell                                          # sell | buy | brands-by | vintage | care | data
   slug: where-to-sell-clothes-belarus                   # совпадает с именем файла
   publishedAt: 2026-11-10                               # день публикации
   updatedAt: 2026-11-10                                 # менять только при реальном обновлении фактов
   author: team                                          # id из client/src/lib/journal-authors.ts
   cover: /journal/where-to-sell-clothes-belarus/cover.jpg   # под client/public, 1280 px по ширине
   coverAlt: "Стопка сложенной одежды и телефон с открытым объявлением"
   tags: [продать, комиссионка, куфар]
   catalog: [sell, resale, c/outerwear]                  # страницы каталога, о которых статья: они покажут её под товарами
   summary:                                              # блок «Коротко», 3–5 законченных тезисов
     - "…"
     - "…"
     - "…"
   faq:                                                  # 4–6 вопросов, ответ 1–3 предложения
     - q: "…"
       a: "…"
   related: [how-to-price-used-clothes, selling-personal-items-taxes-belarus]   # slug других статей
   draft: true
   ---
   ```

   «Коротко» и FAQ рендерятся из `summary` и `faq` автоматически — в тексте их повторять не нужно.
4. Тело — Markdown/MDX. Компоненты, которые можно писать прямо в тексте (`client/src/components/journal/mdx-components.tsx`):
   `<Stat value="…" label="…" source="…"/>` и несколько подряд внутри `<Stats>…</Stats>`;
   `<Quote author="…" role="…">…</Quote>`; `<Callout title="…" tone="note|warn">…</Callout>`;
   `<Compare head={[…]} rows={[[…]]} caption="…"/>`; `<Items path="c/jeans" market="resale" limit={4}/>` — живые лоты;
   `<CtaSell/>` — бэнд «Продайте то, что не носите». Ссылки внутри сайта — обычным Markdown `[текст](/sell)`.
5. Обложка и фото: ширина 1280 px, JPG или WebP, вес до ~300 КБ, папка `client/public/journal/<slug>/`. У каждого
   изображения осмысленный `alt` («Замер ширины джинсов по поясу на столе», не «фото1»); в Markdown — с шириной и
   высотой, чтобы страница не прыгала. Люди на фото — только с их согласия; чужие лица, номера и адреса в кадр не
   попадают.
6. Проверьте локально: `cd client && npm run dev`, откройте `/journal/<slug>` (черновики видны локально). Прогоните
   чек-лист ниже.
7. Поставьте `draft: false`, выставьте `publishedAt` и `updatedAt` на сегодняшнюю дату, закоммитьте и запушьте в
   `main`. Пуш в `main` = деплой = публикация; отдельного шага «опубликовать» нет.
8. После деплоя: страница открывается, есть в `/sitemap.xml` и в RSS журнала; в Яндекс Вебмастере — «Переобход» для
   статьи и хаба рубрики; пост в Telegram-канал с одной цифрой из статьи.
9. Обновите статус в `docs/journal/briefs/README.md`: «опубликована <дата>».

Обновление старой статьи: правите текст, меняете `updatedAt` только если изменились факты, цифры, адреса или год в
заголовке. Косметика (опечатки, ссылки) — без смены даты.

## Чек-лист приёмки

Статья публикуется, когда отмечены все 20 пунктов.

**Факты и цифры**
- [ ] 1. Каждый факт проверен по источнику; ничего не взято «по памяти» или из ИИ-черновика без проверки.
- [ ] 2. Минимум две цифры, у каждой — источник и дата: `<Stat source="…"/>` для данных ichiba, название источника и
      дата проверки для внешних (Белстат, тарифы, нормы, страницы условий магазинов).
- [ ] 3. Минимум одна цитата `<Quote>` с именем и ролью, с согласия человека.
- [ ] 4. Адреса, цены, условия магазинов — с датой проверки в тексте («на ноябрь 2026»); нормы законодательства — с
      названием документа и датой редакции.

**Структура и ответы**
- [ ] 5. Блок «Коротко» (`summary`) — 3–5 тезисов, каждый — законченный ответ, понятный без статьи.
- [ ] 6. Под каждым H2 первым абзацем — прямой ответ 40–60 слов на вопрос заголовка.
- [ ] 7. H2/H3 сформулированы вопросами, как спрашивают люди; ключ есть в H1, лиде и одном H2, не в каждом.
- [ ] 8. FAQ 4–6 вопросов во frontmatter, ответы 1–3 предложения, формулировки из реальных запросов.
- [ ] 9. Таблица или сравнение есть, если бриф его требует.
- [ ] 10. Объём 1200–2500 слов; хаб — ближе к верхней границе.

**Ссылки**
- [ ] 11. Ссылки на каталог: категория или бренд из брифа, `catalog` заполнен; для рубрики sell — `<CtaSell/>` минимум
      дважды.
- [ ] 12. Ссылки на 1–2 другие статьи журнала по slug из брифа и на хаб рубрики; `related` заполнен.
- [ ] 13. Живые лоты `<Items/>` вставлены там, где указывает бриф.

**Текст**
- [ ] 14. Нет воды: каждый абзац отвечает на вопрос или даёт пример; вводные вроде «в современном мире» удалены.
- [ ] 15. Нет переспама: основной запрос ≤ 2–3 % слов, синонимы вместо повторов.
- [ ] 16. Нет контента про сам сервис вместо ответа; минусы ichiba названы там, где они есть. Тон — как у остального
      сайта: спокойно, конкретно, без восклицаний.

**Метаданные и медиа**
- [ ] 17. `title` ≤ 56 символов, `description` ≤ 158 символов, оба с главным запросом, без обрыва на полуслове.
- [ ] 18. `publishedAt` и `updatedAt` честные; год в заголовке совпадает с датой публикации или ревизии.
- [ ] 19. Обложка 1280 px с `coverAlt`, все изображения с `alt`, вес в норме; в кадре нет чужих лиц, номеров и адресов.
- [ ] 20. `draft: false`, `rubric` из шести допустимых, `slug` совпадает с именем файла и брифом, `author` существует
      в `journal-authors.ts`.

После публикации: пост в Telegram, «Переобход» в Вебмастере, статус в README брифов, строка в журнале внешних
упоминаний. Через месяц — посмотреть статью в GSC и Вебмастере, через три — ревизия.
