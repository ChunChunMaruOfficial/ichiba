# Журнал ichiba: стратегия SEO и GEO

Версия для репозитория. Исходный план с исследованием и разбором конкурентов — у владельца; здесь — то, что нужно
автору и разработчику, чтобы раздел `/journal` работал на поиск и на ИИ-ответы.

Сопутствующие документы:
- `docs/journal/briefs/` — 40 брифов-ТЗ на статьи, `README.md` там — сводная таблица.
- `docs/journal/geo-questions.md` — 30 вопросов и таблица ежемесячного среза в ИИ-ответах.
- `docs/journal/author-checklist.md` — как опубликовать статью и чек-лист приёмки.

## 1. Зачем журнал

ichiba.by — маркетплейс открытых гардеробов (б/у, винтаж, локальные бренды) для Беларуси, второй рынок — Россия.
Техническое SEO товаров, брендов и категорий сделано (`server/src/seo/*`, лендинги `/c/...` и `/brands/...`, sitemap,
IndexNow, JSON-LD Product/ItemList/BreadcrumbList/ProfilePage). Контентных страниц нет: сайт ранжируется только по
товарным и брендовым запросам, а по информационным («как продать одежду», «белорусские бренды одежды», «как отличить
подделку») — нет. ИИ-ответам (ChatGPT, Perplexity, Google AI Overviews / AI Mode, Яндекс Нейро) нечего цитировать:
нет текста с фактами, цифрами и ответами на вопросы.

Журнал закрывает обе дыры: информационный трафик из Google и Яндекса по Беларуси и цитируемость в генеративных
ответах. У маркетплейса есть то, чего нет у медиа и конкурентов: собственные данные о ценах, брендах, сроках продажи.
Это главный контентный актив.

Вводные владельца: статьи пишет он сам с ИИ-черновиками; регионы — Беларусь (Google + Яндекс), Россия вторым
рынком; GEO важно уже сейчас; конкуренты — Kufar, Onliner, Instagram/Telegram-магазины; бюджет на инструменты — ноль.

## 2. Выводы исследования

Прочитано 12 источников: гайды Semrush и Ahrefs по e-commerce SEO, GEO-гайд Ahrefs и три исследования цитирований
2025–2026, Google Search Central «AI features», статья GEO Принстона, материалы workspace.ru, Sostav, vc.ru и Kokoc по
Яндексу 2025–2026. Цифры ниже — из этих источников; при цитировании в статьях ссылаться на первоисточник.

| Факт | Следствие для ichiba |
|---|---|
| Главный коррелят попадания бренда в AI Overviews — упоминания на сторонних сайтах (r = 0,664, Ahrefs 2025) | Без внешних упоминаний на BY-медиа и в Telegram контент один не вытянет GEO. Дистрибуция — часть плана |
| В генеративных ответах видимость растут: цитаты экспертов +43 %, статистика +33 %, читабельность +29 %, ссылки на источники +28 %; keyword stuffing −9 % (Princeton GEO) | Каждая статья: цифры с источником + цитата с именем и ролью. Плотность ключа ≤ 2–3 % |
| AI Overviews берут 31 % источников вне топ-100 через fan-out подзапросов (Ahrefs, 03.2026); Яндекс YATI группирует по смыслу | Делать кластеры (хаб + сателлиты), не одиночные статьи |
| Больше всего AI-трафика у страниц «лучшие / топ / как / vs» и у главной + продуктовых страниц | Главная и `/sell` тоже GEO-страницы: кто мы, цифры, FAQ |
| Google: для ИИ-выдачи специальной разметки и файлов не нужно; llms.txt не используется | Разметку делать ради rich results и Яндекса; llms.txt ставим за 10 минут, но не рассчитываем |
| ИИ цитирует контент на 25 % свежее органики, средний возраст 2,9 года | Вечнозелёные хабы + честная ревизия раз в квартал с `dateModified` |
| Яндекс: ответ 40–60 слов сразу после H2, автор с био, единый NAP, Яндекс Бизнес; Турбо закрыты с 04.2025; ИКС — не фактор | Answer-first блоки, авторские карточки, регион «Беларусь» в Вебмастере; Турбо/AMP не делаем |
| Состав цитируемых доменов в ChatGPT меняется за недели (Reddit 60 % → 10 % за месяц) | Не ставить на одну площадку; измерять AI-видимость ежемесячно |

## 4. Архитектура

- **Где живёт контент:** MDX-файлы в репозитории `client/content/journal/<slug>.mdx` с frontmatter
  (`title, description, rubric, slug, publishedAt, updatedAt, author, cover, tags[], faq[], related[], summary[], draft`).
  Без Prisma-модели и админки: автор один, пишет в редакторе, пуш в `main` = публикация, ревью через git. Если появится
  сторонний редактор — мигрировать в базу позже, frontmatter уже совпадёт с полями модели.
- **URL:** `/journal` (индекс), `/journal/<rubric>` (хаб рубрики), `/journal/<slug>` (статья),
  `/journal/authors/<id>` (автор). Подпапка, не поддомен: авторитет домена общий.
- **Рендер:** статика через `generateStaticParams` + ISR; весь текст в HTML (ИИ-краулеры не исполняют JS); живые блоки
  товаров — серверные компоненты.
- **Разметка:** Article (author Person, datePublished/dateModified, image), BreadcrumbList, FAQPage (из frontmatter
  `faq`), ItemList для подборок; Organization + WebSite в корневом layout.
- **Код раздела:** `client/src/app/journal`, `client/src/components/journal`, `client/src/lib/journal.ts`
  (контракт frontmatter), `journal-rubrics.ts` (шесть рубрик с вводными текстами), `journal-authors.ts` (авторы).
  Блоки «Коротко» и FAQ рендерятся из frontmatter `summary` и `faq`; в тексте автору доступны `<Stat/>`, `<Stats/>`,
  `<Quote/>`, `<Callout/>`, `<Compare/>`, `<Items/>` (живые лоты категории или бренда), `<CtaSell/>`.
- **Данные для статей:** `server/scripts/journal-stats.ts` — выгрузка цифр по лотам и сделкам в JSON для `<Stat/>`
  (средние/медианные цены по категориям и брендам, доля б/у, скорость продажи). Пока скрипта нет — цифры запрашиваются у
  владельца и помечаются источником «данные ichiba, дата».
- **Стиль:** тот же язык, что у остального сайта: бумага, Spectral, киноварь только как печать, индиго для ссылок,
  `TitleWithKanji` (журнал — 読物). Никаких «блоговых» шаблонов.

## 5. Шесть рубрик

Шесть рубрик = шесть хабов, у каждого свой запросный кластер и бизнес-цель. Хаб рубрики — страница `/journal/<rubric>`
с вводным текстом 150–250 слов, который сам по себе отвечает на запрос рубрики, плюс первая статья-хаб из списка.

| Рубрика (slug) | Цель | Ядро запросов | Куда ведёт | Статья-хаб |
|---|---|---|---|---|
| Продать (`sell`) | новые продавцы | как продать одежду, где продать б/у, сколько стоит, как сфотографировать | `/sell` | `where-to-sell-clothes-belarus` |
| Купить и не прогадать (`buy`) | доверие покупателей | как отличить оригинал, что проверить, размерные сетки, как торговаться | `/c/...`, `/resale` | `online-clothing-auction-belarus` |
| Бренды Беларуси (`brands-by`) | трафик + внешние упоминания | белорусские бренды одежды, обуви, сумок; «бренд X отзывы/размеры» | `/brands/<slug>` | `belarusian-clothing-brands-2026` |
| Винтаж и секонд (`vintage`) | ниша с низкой конкуренцией | винтажные магазины Минска, как определить винтаж, лейблы по годам | `/resale` | `what-is-vintage-clothing` |
| Уход и ремонт (`care`) | вечнозелёный инфо-трафик | как стирать пуховик/кашемир, убрать катышки, растянуть обувь | карточки категорий | хаба нет, вводный текст рубрики |
| Цены и данные (`data`) | уникальные цифры, PR, GEO | сколько стоит б/у X в Беларуси, индекс цен, что продаётся быстрее | весь каталог | `used-clothes-price-index-belarus` |

Все 40 тем с приоритетами — в `docs/journal/briefs/README.md`. Приоритеты: П1 — первый месяц (хабы, «продать»,
«бренды», индекс цен), П2 — месяцы 2–3, П3 — далее. Частотности запросов автор проверяет в Вордстате с регионом
«Беларусь» на этапе брифа; в брифах они не выдуманы и не приводятся.

## 6. Правила написания под поиск и ИИ-ответы

1. **Answer-first.** Сразу под лидом — блок «Коротко»: 3–5 тезисов, каждый — законченный ответ. Это то, что
   цитируют ИИ и читают люди с телефона. Хранится во frontmatter `summary[]`.
2. **Прямой ответ под каждым H2.** Первый абзац после заголовка — 40–60 слов, отвечающих на вопрос заголовка без
   подводок. Подробности и оговорки — ниже.
3. **Заголовки — вопросами.** H2/H3 формулируются так, как спрашивают люди («Сколько берёт комиссионка в Минске?»),
   потому что ИИ раскладывает запрос на подвопросы и ищет совпадения.
4. **Цифры с источником.** Минимум две на статью. Своя статистика ichiba — через `<Stat value source/>` с датой
   выгрузки; внешняя — Белстат, официальные тарифы, нормы законодательства, страницы условий магазинов — с названием
   источника и датой проверки. Цифра без источника не публикуется.
5. **Цитаты с именем и ролью.** Минимум одна на статью: продавец с платформы, стилист, товаровед комиссионки,
   технолог химчистки, основатель бренда. Только с согласия человека; в репозиторий имена и контакты не попадают — они
   живут в тексте статьи.
6. **FAQ 4–6 вопросов** во frontmatter `faq[]`: реальные формулировки из хвостов, короткие ответы 1–3 предложения.
   Рендерится как `details`, размечается FAQPage.
7. **Внутренние ссылки 3–5:** категория или бренд каталога, 1–2 статьи журнала, хаб рубрики. Живые лоты через
   `<Items/>` — чтобы журнал вёл в товары.
8. **Без keyword stuffing.** Плотность основного запроса ≤ 2–3 %. Синонимы и естественная речь. Ключ в H1, в первом
   абзаце, в одном H2 — достаточно.
9. **Локальная конкретика.** Рубли, Минск и города площадки, белорусские размеры, местные тарифы. Это то, чего нет
   у RU-источников и что выделяет нас в выдаче по Беларуси.
10. **Честные даты.** `publishedAt` — день публикации, `updatedAt` — только когда реально изменили факты или цифры.
    Ревизия раз в квартал: цены, лоты, адреса, год в заголовке.
11. **Автор с био.** Карточка автора с ролью и ссылками (Person в Article) — для E-E-A-T и Яндекса.
12. **Объём 1200–2500 слов.** Хабы — ближе к верхней границе. Короче — не закроет запрос, длиннее — вода.
13. **Запрещено:** выдуманные факты, адреса и цены; контент про сам сервис вместо ответа на вопрос; пакетная заливка
    одной датой; статьи без ссылок на каталог.

## 7. Дистрибуция без бюджета

Внешние упоминания — главный коррелят попадания в ИИ-ответы, поэтому дистрибуция — часть каждой публикации, а не
опция.

- Telegram-канал ichiba: каждая статья → пост с одной цифрой и ссылкой; репосты у продавцов-магазинов, которые уже на
  платформе.
- Питч BY-медиа данными: «Индекс цен на б/у одежду в Беларуси» и другие data-статьи — в Onliner, dev.by, CityDog,
  KYKY, The Village. Цель — упоминание бренда, не обязательно ссылка.
- Попадать в подборки «где купить/продать одежду в Беларуси», «белорусские бренды»: комментарии и письма авторам
  существующих материалов.
- Дзен + RSS (`/journal/feed.xml`), VC.ru (переупаковка data-статей), ответы на Пикабу, форумах, Яндекс Кью — не чаще,
  чем по делу.
- Короткие видео (Reels/Shorts/TikTok) по статьям с упоминанием ichiba.by — YouTube самый цитируемый домен в AI
  Overviews.
- Никаких покупных ссылок и накрутки поведенческих факторов (фильтры Минусинск/Баден-Баден, 2–6 месяцев
  восстановления).

## 8. Ритм и KPI

- **Темп:** 1 статья в неделю первые 2 месяца (сначала хабы, «продать», «бренды», индекс цен), затем 6–8 в месяц.
  Раз в квартал — ревизия 10 старых статей (цены, лоты, даты, год в H1).
- **Ориентиры:** 3 месяца — 30 статей, первые позиции в топ-10 по низкочастотке BY, первые цитаты в Perplexity и
  Нейро (примерно через 2 месяца после индексации); 6 месяцев — журнал даёт ≥ 20 % органики и измеримые регистрации
  продавцов.
- **Цели Метрики** (`lib/analytics.ts`): `article_read` (70 % скролла), `article_cta_sell`, `article_item_click`,
  `article_faq_open`.

## 9. Что не делаем и почему

| Не делаем | Почему |
|---|---|
| Турбо-страницы, AMP | Турбо закрыты Яндексом с 04.2025; AMP не нужен для ранжирования |
| Покупные ссылки, накрутка ПФ | Фильтры Минусинск/Баден-Баден, 2–6 месяцев восстановления |
| Отдельный поддомен блога | Дробит авторитет домена; подпапка `/journal` наследует его |
| Перевод на белорусский/английский | Не выбран владельцем; пока один язык |
| Админка для статей | Автор один, git и MDX достаточно; миграция в базу — когда появится второй редактор |
| Ставка на llms.txt | Google его не использует; ставим, но не рассчитываем |
| Статьи про сам сервис | Так делает Kufar и не ранжируется; пишем ответы на вопросы людей, CTA — внутри |
| Пакетная публикация одной датой | Признак SEO-свалки у secondhand.by/mamaland; ровный ритм и честные даты |
| Контент без цифр и цитат | Именно они дают +33 % и +43 % видимости в ИИ-ответах |

## 10. Ежемесячный чек-лист измерений

Первый срез («нулевой») снимается до публикации первой статьи, чтобы было с чем сравнивать.

**Google Search Console**
- [ ] Показы и клики по URL с префиксом `/journal` (отдельно хабы и статьи).
- [ ] Новые запросы, по которым появились показы; позиции 4–20 — кандидаты на доработку.
- [ ] Покрытие: все опубликованные статьи проиндексированы, нет «обнаружена — не проиндексирована» старше 2 недель.
- [ ] Rich results: Article и FAQPage без ошибок.

**Яндекс Вебмастер**
- [ ] Регион «Беларусь» выставлен; показы и клики по `/journal`.
- [ ] Статистика обхода: новые статьи обойдены; «Переобход» для хабов после обновлений.
- [ ] Качество: нет предупреждений о переоптимизации или малополезном контенте.
