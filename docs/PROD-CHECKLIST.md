## 3. Безопасность (что проверено и чем закрыто)

- **Транспорт и заголовки.** helmet на API; на сайте CSP (`script-src 'self' 'unsafe-inline'` + провайдеры входа,
  `object-src 'none'`, `base-uri`, `form-action`, `frame-ancestors 'none'`), HSTS, nosniff, Referrer-Policy,
  Permissions-Policy; приватные разделы — `Cache-Control: private, no-store` + `X-Robots-Tag: noindex`.
  Проверено curl'ом на https://ichiba.by. ✅
- **Сессии.** JWT в httpOnly-cookie (secure, SameSite=Lax; админ — Strict), отдельная 8-часовая админ-сессия.
  Новое: `User.sessionVersion` в токене — смена пароля, блокировка и удаление аккаунта убивают все сессии. ✅
- **Регистрация.** Пароль и ник живут внутри кода подтверждения (`VerificationCode.payload`); строка `User`
  появляется только когда владелец адреса ввёл код — чужой пароль на чужой адрес повесить нельзя. Попытки ввода
  кода считаются атомарно (5 на код), лимит кодов — на адрес и цель. ✅
- **Rate limit.** Ключ — аккаунт, для гостей `X-Real-IP` (его ставит edge Railway, затирая клиентский; `X-Forwarded-For`
  edge переписывает в «посетитель, узел edge», поэтому `trust proxy = 2`). Проверено на проде: 25 неверных входов с
  подделанными `X-Forwarded-For` и `X-Real-IP` → 429. При недоступном Redis лимиты отключаются, а не роняют сайт в 500. ✅
- **WebSocket.** Ошибка кадра больше не роняет процесс (обработчики `error`), проверка Origin, до 10 сокетов на
  аккаунт, cookie-путь проверяется как HTTP-сессия. Проверено сквозным скриптом. ✅
- **Авторизация.** Владение проверяется в сервисах на каждой мутации (объявления, сделки, предложения, аукционы,
  отзывы, коллекции, чаты). Проданные и скрытые админом вещи нельзя переписать в обход модерации. ✅
- **Гонки.** Закрытие аукциона, автозавершение сделок, отклонение предложений, публикация по расписанию —
  в транзакциях с блокировкой строки и guard-ом по статусу; частичные уникальные индексы (один активный аукцион,
  одно pending-предложение). Все cron-задачи под `withJobLock` (Redis `SET NX` + in-process). ✅
- **Загрузки.** Лимит 50 Мп на картинку, не больше двух одновременных sharp-пайплайнов, видео-постер ≤ 5 МБ,
  `.mov` локально отклоняется (GPS-метаданные), MP4 чистится от `udta/meta`. Ошибка размера — по-русски. ✅
- **Импортёры (Telegram, магазины).** Только https, allowlist хостов, ручные редиректы, тело ≤ 15 МБ, таймауты;
  импортёр не трогает аккаунт, за которым стоит живой человек (email/телефон/OAuth). ✅
- **ИИ.** Пользовательский текст передаётся как данные с явной рамкой «не инструкции»; попытки инъекции уходят на
  ручную проверку; антифрод чата жалуется только при сигнале правил; бюджет публичных ИИ-функций и слот для
  модерации объявлений. ✅
- **Админка.** Обозреватель БД: нельзя фильтровать/сортировать по секретным колонкам, нельзя удалять `User`,
  `Listing`, `Thread`, `Message`, `ModerationAction`, `BuyRequest`, `Review`, `Report`. ✅
- **Что остаётся на совести конфигурации:** `JWT_SECRET` ≥ 32 символов, `NODE_ENV=production`, `WEB_ORIGIN` без
  лишних доменов, резервные копии Postgres включены в Railway.

## 5. Функционал (прогон в браузере на тестовой базе с демо-данными)

Гость: главная, поиск, «Вторичка», вещь, гардероб, 404 для несуществующей вещи (настоящий 404-статус). ✅
На проде после деплоя: `/health` 200 с базой и Redis, 404 для несуществующей вещи (и для Googlebot), `/search`
noindex, sitemap без `/search`, 413 по-русски на 16 МБ, WebSocket: чужой путь 404, без сессии 401, чужой Origin 403,
API жив после проб; миграция применилась, backfill палитр прошёл по всем фото. ✅
Пользователь: вход по паролю, избранное, корзина, оформление покупки (с `expectedTotal` → 409 при смене цены),
сделка в «Покупках», чат с продавцом, уведомления, настройки, форма продажи. ✅
Админ: вход в админку, сводка, обозреватель базы. ✅
Не прогонялось руками: загрузка фото из браузера (нет инструмента выбора файла в тестовом браузере; проверено
только через API), вход через Google/Telegram/Apple (нужны боевые ключи), письма (в тестовом окружении
отправка выключена).

## 6. Совместимость

- Базовая поддержка: Chrome/Edge/Firefox 111+, Safari 16.4+ (то, что собирает Next 16 и требует Tailwind 4).
  iOS 15 и 16.0–16.3 не поддерживаются — стоит упомянуть в требованиях.
- Проверено по коду и в эмуляции 375×812: `color-mix` с запасными цветами, `-webkit-backdrop-filter`,
  safe-area, `interactiveWidget: resizes-content` (клавиатура Android в чате), `pointerdown` вместо `mousedown`
  для закрытия по тапу (iOS), запрет зума полей (16px), reduced-motion, жесты на pointer events, canvas в
  редакторе фото без утечек памяти (iOS), HEIC-превью после загрузки.
- Доступность: axe (AA + best practices) на главной, поиске, вещи, гардеробе — 0 серьёзных нарушений после
  добавления `h1`; видимый фокус у кнопок и чипов; ловушка фокуса и `inert` в модалках; `error.tsx` по-русски.
- ⏳ Руками на реальном iPhone: поле поиска на мобильной странице `/search` (в эмуляции встроенного браузера
  поле есть в DOM и принимает фокус, но на снимке не отрисовывается — так же и на проде; скорее всего артефакт
  снимка, но проверить на устройстве). Остаточный CLS 0.05 — шапка подрастает с 35 до 44 px после гидрации.

## 7. Деплой (Railway)

1. Пуш в `main` ничего не деплоит: после пуша — деплой `server` и `client` через Railway (MCP `railway-agent`).
2. Pre-deploy `npx prisma migrate deploy` применит `20261105090000_hardening` (только `ADD COLUMN`/`CREATE INDEX`,
   безопасно для старого кода во время переключения).
3. У `client` переменная `API_URL` должна быть видна на этапе сборки — иначе сборка теперь падает (раньше тихо
   подставлялся localhost).
4. После деплоя: `GET /health` → `{"ok":true,"db":true,"redis":true}` (503 без базы), вход, чат по WebSocket,
   одна покупка на тестовой вещи.
5. Бэкапы Postgres → включить расписание в Railway, если ещё нет.

## 9. Что ещё стоит сделать (не блокирует релиз)

- Observability: structured-логи (`nestjs-pino`), request-id; ошибки уже приходят в Telegram (пункт 8), Sentry не нужен до роста.
- `EmailOutbox` не используется: либо реализовать очередь писем о сделках, либо убрать таблицу и упоминания.
- Триграммный индекс для поиска при росте каталога; keyset-пагинация вместо `offset`.
- Экспорт персональных данных (право на доступ сейчас только в политике).
- Вход через Apple без шага согласия с политикой (остальные провайдеры его проходят).
- Полноценный учёт пропусков гостя в свайпе на сервере (в URL уходят последние 60).
