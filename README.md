# ichiba — маркетплейс открытых гардеробов

MVP по спецификации с Miro-доски «Wardrobe Marketplace». Две независимые части, у каждой свой `package.json` и `package-lock.json`:

- `server` — NestJS 12 (ESM) + Prisma 7 + PostgreSQL. REST API, WebSocket-чат, фоновые задачи.
- `client` — Next.js 16 + Tailwind 4. Браузер ходит в API через `/api/*` (rewrite в `client/next.config.ts`), поэтому сессионная кука first-party.

## Деплой (всё на Railway)

Один репозиторий, один проект Railway `ichiba`, четыре сервиса:

| Сервис | Что это | Настройки |
|---|---|---|
| `Postgres` | база (шаблон Railway) | — |
| `Redis` | шина событий чата между копиями сервера, лимиты | — |
| `server` | репозиторий, **Root Directory `/server`**, Watch Paths `/server/**` | Build `npm run build`, Pre-deploy `npx prisma migrate deploy`, Start `node dist/main.js`, Healthcheck `/health`; volume `/data` для фото без Cloudinary |
| `client` | репозиторий, **Root Directory `/client`**, Watch Paths `/client/**` | Railpack сам: `npm run build` → `npm start`; Healthcheck `/` |

Каждый пуш в `main` пересобирает только тот сервис, чья папка изменилась. Настройки сборки заданы в самом сервисе Railway (config-as-code `railway.json` Railway больше не поддерживает).

**server → Variables:**

```
PORT=4000
DATABASE_URL=${{Postgres.DATABASE_URL}}
DATABASE_POOL_MAX=10
REDIS_URL=${{Redis.REDIS_URL}}
REALTIME_DRIVER=ws
WEB_ORIGIN=https://${{client.RAILWAY_PUBLIC_DOMAIN}}
APP_URL=https://${{client.RAILWAY_PUBLIC_DOMAIN}}
ADMIN_EMAILS=c4erkaoui@gmail.com
MEDIA_DRIVER=local  MEDIA_DIR=/data/media  MEDIA_PUBLIC_URL=https://${{RAILWAY_PUBLIC_DOMAIN}}/media
AUTH_DEV_ANY_CODE=false  SEED_DEMO=false
# секреты — вписать вручную:
JWT_SECRET=<openssl rand -base64 48>
GMAIL_CLIENT_ID=…  GMAIL_CLIENT_SECRET=…  GMAIL_REFRESH_TOKEN=…  SMTP_FROM=<тот же Gmail>  # почта через Gmail API: Railway Hobby блокирует SMTP
TELEGRAM_BOT_TOKEN=…  TELEGRAM_BOT_USERNAME=…               # вход через Telegram (@BotFather, /setdomain)
CLOUDINARY_CLOUD_NAME=…  CLOUDINARY_API_KEY=…  CLOUDINARY_API_SECRET=…   # иначе фото лежат на volume
GEMINI_API_KEY=…  MISTRAL_API_KEY=…  ZAI_API_KEY=…                       # по желанию, ИИ
```

**client → Variables:**

```
PORT=3000
API_URL=http://${{server.RAILWAY_PRIVATE_DOMAIN}}:4000   # внутренняя сеть Railway
NEXT_PUBLIC_SITE_URL=https://${{RAILWAY_PUBLIC_DOMAIN}}
NEXT_PUBLIC_LEGAL_EMAIL=c4erkaoui@gmail.com
NEXT_PUBLIC_LEGAL_OPERATOR=<ИП или организация>   NEXT_PUBLIC_LEGAL_UNP=<УНП>   NEXT_PUBLIC_LEGAL_ADDRESS=<адрес>
```

Чат работает по WebSocket прямо с сервера (`wss://<домен server>/ws`, адрес сервер берёт из `RAILWAY_PUBLIC_DOMAIN` сам). Фоновые задачи (аукционы, 48-часовые сроки, очередь писем, чистка фото) крутятся внутри процесса. Проверка: `https://<домен server>/health` → `{"ok":true,"db":true,…}`.

Свой домен: client → Settings → Networking → Custom Domain. Благодаря ссылкам `${{…}}` `WEB_ORIGIN`, `APP_URL` и `NEXT_PUBLIC_SITE_URL` подхватят его сами (`NEXT_PUBLIC_*` — после пересборки client).

**Бэкапы базы:** Postgres → Backups, включить расписание.

**Администратор.** Зарегистрируйтесь на сайте с email из `ADMIN_EMAILS` и подтвердите код — аккаунт станет администратором; вход в `/admin` — по паролю.

**Демо-данные (моки)** отключены, но не удалены (`server/prisma/seed*.ts`): запускаются только локально командой `SEED_DEMO=true npm --prefix server run seed` и никогда в production.

Сервер можно выложить и на Vercel/другой serverless (тогда нужны `PUSHER_*` для чата и `CRON_SECRET` для `/cron/tick`), и на любой VPS (там подойдёт обычный SMTP: `SMTP_HOST/PORT/SECURE/USER/PASS`). С Supabase вместо Postgres Railway: `DATABASE_URL` = Session pooler; миграция `supabase_rls` сама добавит политики RLS (на обычной Postgres она только включает RLS).

## Локальный запуск (без Docker)

Нужен Node 22+.

```bash
# server/.env: минимум PORT=4000, WEB_ORIGIN=http://localhost:3000, JWT_SECRET=<случайная строка>,
#   DATABASE_URL=postgres://postgres:postgres@localhost:51214/template1?sslmode=disable, DATABASE_POOL_MAX=1,
#   AUTH_DEV_ANY_CODE=true; ключи — по таблице «Опциональные ключи» ниже
npm run install:all                  # зависимости корня, server и client
npm run dev                          # база (prisma dev), миграции, сервер на :4000, сайт на :3000
```

`npm run dev` сам поднимает локальный Postgres, ждёт его, применяет новые миграции и запускает сервер и сайт. Для первого запуска можно также `npm run setup` (нужна запущенная база: `npm run db`).

Тестовые аккаунты и вещи: `SEED_DEMO=true npm --prefix server run seed` (пароль у всех `password123`, админ `admin@ichiba.test`). Пересоздать с нуля: `SEED_DEMO=true npm --prefix server run seed -- --reset`.

`prisma dev` держит одно соединение, поэтому локально `DATABASE_POOL_MAX=1`. Новые миграции на `prisma dev` создаются через `prisma migrate diff` + `prisma migrate deploy`: `migrate dev` не может создать shadow-базу.

Коды подтверждения в dev печатаются в лог сервера. Пока стоит `AUTH_DEV_ANY_CODE=true`, подходит любой код из 6 цифр; при `NODE_ENV=production` режим отключается.

Без `CLOUDINARY_*` фото хранятся в `server/storage/media` и раздаются сервером по `/media`.

## Cloudinary

- **Cloudinary** — файлы фото. Браузер берёт у API подпись (`POST /media/photos/ticket`) и грузит файл прямо в Cloudinary. Секрет есть только у API. Затем API проверяет подпись ответа Cloudinary и папку пользователя (`ichiba/<userId>/`), размер (от 400 px), считает хеш для поиска дублей и сохраняет в таблице `Photo` public_id, URL, версию, формат, размер, порядок и обложку. Оригинал при загрузке ужимается до 2560 px, EXIF и GPS удаляются. На витрину отдаются `f_auto,q_auto` превью 320/640/1280. Файлы, которые сутки не привязаны к объявлению (форму бросили, фото убрали при редактировании), ночью удаляются из Cloudinary. Проверка всего пути: `node _e2e-cloudinary.mjs`.

- ♡ = сохранить + следить: уведомления о снижении цены, резерве и продаже.

- Мои покупки и Мои продажи, страница сделки с трекером, споры.

## Аукцион (решение D16, фрейм 34 на доске)

- В Add Item на шаге цены переключатель «Фиксированная цена / Аукцион»: старт, шаг (по умолчанию 5%), 1 / 3 / 7 дней, необязательная скрытая резервная цена.
- Ставка в последние 5 минут продлевает аукцион. Пока он идёт, нет «Купить», оффера и корзины; цена заморожена; отменить можно до первой ставки.
- Закрытие раз в минуту. Победитель получает сделку ACCEPTED и выбирает способ получения за 48 ч, иначе вещь уходит следующей ставке не ниже резерва или возвращается в продажу.
- Чип «Аукционы» на главной, таймер на карточках, вкладка «Ставки» в «Мои покупки». Демо-аукционы добавляет `SEED_DEMO=true npx tsx prisma/seed-auctions.ts` (из папки `server`) (входит в основной сид).

## ИИ-ансамбль

Каждый запрос уходит параллельно во все живые модели (Google Gemini, Mistral, Z.ai GLM), ответы проверяются по zod-схеме и сводятся голосованием: большинство, медиана, кворум. Код в `server/src/ai/`.

- **Надёжность.** У каждого провайдера цепочка моделей (перегружена или нет квоты → следующая), очередь под лимиты бесплатных тарифов и автоотключение по модели: 429 у vision-модели не выключает текстовую. Общий дедлайн; после первого ответа остальным даётся короткое окно, чтобы медленный провайдер не тормозил пользователя.
- **Решения с последствиями.** Отказ в публикации требует строгого большинства моделей. Одна модель может только отправить объявление на ручную проверку; детерминированное правило может выступить вторым голосом.
- **Без моделей** работают правила (`text-rules.ts`). Объявления, опубликованные без ИИ, помечаются `unchecked` и перепроверяются cron'ом.
- **Журнал.** Каждый вызов пишется в таблицу `AiRun`: модели, задержка, токены, голоса. Здоровье провайдеров и статистика — в админке на главной.

| Функция | Где | Как решается |
|---|---|---|
| Автозаполнение | Add Item, шаг 2 | голосование по каждому полю |
| Проверка фото | Add/Edit Item | яркость, резкость, разрешение (sharp) + голоса vision-моделей: вещь видна, лучшая обложка, каких кадров не хватает |
| Подсказка цены | шаг цены, Edit Item | похожие вещи площадки (с поправкой на состояние, бренд, проданные) + медиана оценок моделей |
| Совет в торге | «Мои продажи», карточка вещи у покупателя, форма предложения | правило + модели голосуют accept/counter/decline; сумма встречного предложения — медиана, всегда в допустимом диапазоне; скрытый минимум продавца покупателю не утекает |
| Умный поиск | /search | парсер правил + модели → фильтры каталога (`subcategory`, `style` и др.), баннер «Подобрали фильтры… · Искать как текст» |
| Автомодерация | публикация и правка живого объявления | правила (мат, контакты, бессмыслица, «реплика») + модели: в названии вещь, совпадает с категорией и фото, запрещёнка, неприемлемые фото |
| Антифрод чата | чат | номера карт маскируются до сохранения; правила + модели с контекстом переписки; предупреждение получателю в реальном времени (WebSocket); 2+ опасных сообщения за сутки → жалоба в очередь модерации |

E2E: `cd server && node _e2e-ai.mjs` (33 проверки на живых моделях).

## Итерация 3

- **Отзывы** (покупатель → продавец): после завершённой сделки, 1–5 ★, теги, текст; правка 14 дней; публичный ответ продавца; рейтинг в карточке вещи и в гардеробе, вкладка «Отзывы» со сводкой и фильтром по оценке; напоминание через 3 дня; жалоба на отзыв → модератор скрывает.
- **Аукцион: автоставки и «Купить сейчас».** Автоставка как на eBay: система ставит за вас на шаг выше конкурента, не выше вашего лимита (лимит никто не видит, при равных лимитах побеждает ранний). «Купить сейчас» доступна, пока ставка ниже 75% цены выкупа; выкуп сразу создаёт сделку. Ставки сериализуются блокировкой строки — гонок нет.
- **Подбор размера.** В настройках — размеры (одежда, джинсы, обувь) и замеры тела. На вещи: «Скорее всего, подойдёт / может сесть плотно / будет мала» — по замерам вещи (в разложенном виде) с запасом посадки для каждого типа одежды, иначе по размеру на бирке. Фильтр «Мой размер» в поиске.
- **Скидка за комплект.** Продавец задаёт до трёх ступеней («от 2 вещей −10%, от 3 −15%»); скидка применяется в корзине и в запросе, цены по вещам распределяются так, чтобы сумма сходилась; подсказка «добавьте ещё 1 вещь — −15%».
- **Поднятие и статистика.** «Поднять в ленте» — бесплатно, раз в 72 часа (первый раз через сутки после публикации). Статистика по дням: просмотры, ♡, корзина, чаты, предложения, запросы, продажи и выручка с сравнением с прошлым периодом, воронка, советы по каждой вещи. Страница `/sales/stats` и карточка на странице вещи.
- **SEO.** Страницы вещей и гардеробов рендерятся на сервере (готовый HTML), title/description/canonical/Open Graph, микроразметка Product + Offer + BreadcrumbList и ProfilePage, `sitemap.xml`, `robots.txt`, честный 404. Серверный рендер не считается просмотром.
- **Email.** Коды подтверждения и события по сделкам через Nodemailer: очередь с повторами, отписка в один клик, настройка в профиле. Инструкция — [docs/EMAIL.md](docs/EMAIL.md).

E2E: `cd server && node _e2e-v3.mjs` (нужен SMTP-приёмник `node _smtp-capture.mjs` и API с `SMTP_HOST=127.0.0.1 SMTP_PORT=2525`).

## Вход, SMS и персональные данные

- **Вход без пароля** (как на Avito, Kufar, Vinted): Google или телефон/почта → код из 6 цифр → для новых — ник и согласие на обработку данных. Аккаунт создаётся только после согласия; вход по паролю оставлен для тех, у кого он есть. Номера понимаются в любом белорусском формате (`8 029…`, `29…`, `+375…`); на Android код подставляется из SMS сам (WebOTP).
- **SMS:** SMSC.ru (`SMS_PROVIDER=smsc`, `SMSC_LOGIN`, `SMSC_PASSWORD`, `SMSC_SENDER`). SMS уходят только на разрешённые коды стран (`SMS_ALLOWED_PREFIXES`, по умолчанию `+375`) — защита от «накрутки» SMS; лимиты: 1 код в минуту и 5 в час на номер, 30 запросов в час с IP.
- **Политика конфиденциальности** — `/privacy` (Закон РБ № 99-З). Реквизиты оператора — в `client/.env.local` (`NEXT_PUBLIC_LEGAL_*`); незаданные реквизиты просто не выводятся, почта для обращений по умолчанию — `c4erkaoui@gmail.com`. Обработчики (Railway, Cloudinary, почта, SMSC, модели ИИ) перечислены в тексте. Версия согласия хранится у пользователя (`privacyVersion`).
- **Удаление аккаунта** в настройках: контакты и профиль стираются сразу, сделки и переписка остаются у второй стороны обезличенно; сессии удалённых и заблокированных аккаунтов перестают работать.
- **Сроки хранения** выполняются автоматически каждую ночь: коды — 1 сутки, письма — 30 дней, журнал ИИ — 90 дней, прочитанные уведомления — 180 дней, просмотры и свайпы — 12 месяцев.
- Уведомление о cookie внизу страницы (только необходимые cookie, без трекеров).
- **Админка** — только по адресу `/admin` (в меню её нет): вход по логину и паролю аккаунта с ролью ADMIN, отдельная админ-сессия на 8 часов, 5 попыток за 15 минут.

E2E: `cd server && node _e2e-auth.mjs`.

## Каталог, бренды и создание объявления

- **База брендов: ~5 100 брендов** одежды, обуви, сумок и украшений (Wikidata, справочник брендов OpenStreetMap и ручной список с белорусскими и российскими марками). Выбор бренда в форме с поиском по опечаткам и русским написаниям («найк» → Nike), подсказка «в названии бренд Adidas — указать». Свой бренд тоже можно вписать. Пересборка: `node server/scripts/brands/build.mjs`.
- **Каталог в шапке** (кнопка «Каталог»): «Женщинам / Мужчинам», категории и подкатегории, бренды; на телефоне — выезжающее меню.
- **Для кого:** женское или мужское. Не выбрано — вещь подходит всем и показывается и в «Женщинам», и в «Мужчинам» (кроме юбок и платьев).
- **Черновик сохраняется сам**, на `/sell` есть напоминание о незаконченном черновике; **«Выставить похожую»** берёт описание, бренд, цену и категорию из своей вещи.
- **Замеры со схемой:** только нужные для категории поля и подсказка, как мерить.
- **Цена в магазине** → «−70% от цены в магазине» на карточке и странице вещи.
- **Автоотказ и автопринятие** предложений цены по порогам продавца.
- **Видео** до 30 секунд (MP4/MOV/WEBM, до 40 МБ), последним слайдом в галерее; кадр-обложка проходит модерацию вместе с фото.
- **Несколько размеров:** вещь публикуется копиями — по объявлению на размер, на странице вещи переключатель размеров.
- **Отложенная публикация** на время до 30 дней вперёд; объявление проверяется сразу, публикует cron.
- **Скидка лайкнувшим:** личная цена всем, кто сохранил вещь, на 48 часов; раз в 3 дня, не ниже 50% цены.

E2E: `cd server && node _e2e-v4.mjs`.
